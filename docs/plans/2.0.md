# Plan: npm 2.0 major

Working branch: `chore/2x-major` (from `master` / **1.6.3**). Current package version: **2.0.0-alpha.1**.

This is the first **published** major after the 1.x line. It is **not** a continuation of the historical git tags `2.0.0`–`2.5.1` (those were internal milestones folded into **1.3** / **1.5** and were never on npm — see [release notes index](../release-notes/README.md#internal-milestones-removed)).

There is no prior written 2.0 roadmap; this document is the working plan. Scope decisions are locked below.

## Goals

1. Make **Opaque / Remove** the only public naming (finish what 1.6 soft-deprecated).
2. Prefer **safe-by-default** construction over the legacy “redact everything” default.
3. Shrink the accidental public type surface.
4. Ship a clear **1.6 → 2.0** migration guide, CHANGELOG, and release notes.

Non-goals for 2.0.0 (unless explicitly pulled in later):

- Dry-run single-pass attribution during traversal (deferred; perf/complexity).
- New redaction features (better as 2.1+).
- Changing path-rule, value-pattern, or copy-on-write semantics.

## Themes

### 1. Finish Opaque / Remove naming (highest confidence)

Drop soft-deprecated dual naming that 1.6 already warned about:

| Remove | Keep |
| --- | --- |
| `fullSecretKeys` / `deleteSecretKeys` | `opaqueSecretKeys` / `removeSecretKeys` |
| `CustomObjectMatchType.Full` / `.Delete` | `.Opaque` / `.Remove` |
| Builder `.delete()` | `.remove()` |
| Dry-run `action: 'delete'` / `deletedPaths` | `remove` / `removedPaths` (or equivalent) |

Also:

- Strip alias merge in config normalize / `SecretManager`.
- Update guides that still lead with Full/Delete (e.g. metadata redaction).
- Remove construct-time deprecation warnings once the aliases are gone.

**Decision:** Dry-run rename is **in scope** for 2.0.

**Key paths today:** `src/types.ts`, `src/config/configValidator.ts`, `src/config/redactionRules.ts`, `src/rules/secretManager.ts`, `src/api/fieldRedactorConfigBuilder.ts`, dry-run types / reports.

### 2. Safe-by-default construction

Today bare `new FieldRedactor()` with no rules still redacts **everything** (with a warning). `createSafe` / builder `buildSafeRedactor()` already require explicit rules.

| Option | Behavior | Notes |
| --- | --- | --- |
| **A (chosen)** | Require explicit rules — reject empty config (align with `createSafe`) | Clearest major; matches anti-patterns docs |
| B | Keep constructor but default to no-op / pass-through unless rules are set | Rejected |
| C | Leave default; only document `createSafe` harder | Rejected |

**Decision:** Option **A** — empty config is an error (same bar as `createSafe`).

**Key paths:** `src/api/fieldRedactor.ts`, `docs/guides/anti-patterns.md`, `docs/reference/config.md`, `README.md`.

### 3. Shrink public type surface

Stop exporting incidental types marked `@internal` from the package root. Keep them usable internally.

Candidates (re-exported from `src/index.ts` today):

- `JsonFunction`
- `JsonLeafValue`
- `RedactablePrimitive`
- `RedactedPrimitive`
- `SecretSpecifierValue`
- `TraversableJson`

Consumers who imported these would break (expected to be rare). Types remain available for internal use; they are no longer part of the public package export surface.

**Decision:** Root-export removal is **in scope** for 2.0.

### 4. Housekeeping (low risk)

- Rename `objectRedactor.*` tests / helpers to match `ObjectRedactorTraversal` (or current public naming).
- Finalize [migration-1.6-to-2.0.md](../guides/migration-1.6-to-2.0.md) (draft exists), CHANGELOG `[2.0.0]`, `docs/release-notes/v2.0.0.md`.
- Clarify historical `docs/release-notes/2.x.md` archaeology vs npm **2.0.0** in the release-notes index (labeling only; do not delete archaeology unless desired).

## Out of scope (unless pulled in)

| Item | Why |
| --- | --- |
| Dry-run single-pass attribution during traversal | Deferred earlier; complexity vs benefit |
| New redaction features | Prefer 2.1+ after a clean break |
| Path-rule / value-pattern / COW behavior changes | Stable preferred APIs in 1.6 |
| Resurrecting historical internal `2.x` tag semantics | Archaeology only; not the npm line |

## Decisions

| Topic | Choice |
| --- | --- |
| Constructor empty-config | **A** — require explicit rules (align with `createSafe`) |
| Dry-run `delete` → `remove` rename | **Yes** |
| Remove `@internal` root exports | **Yes** |
| Other breaks | None beyond this plan |

No further scope decisions are open for 2.0.0 unless new items are explicitly added.
