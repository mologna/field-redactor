# 2.0 breaking surface

Concrete breaking changes for npm **2.0.0**, derived from [docs/plans/2.0.md](2.0.md). Use this as the implementation checklist; the consumer-facing narrative lives in [migration-1.6-to-2.0.md](../guides/migration-1.6-to-2.0.md).

Baseline: **1.6.3**.

## Summary

| Area | Break type | Consumer impact |
| --- | --- | --- |
| Opaque/Remove-only naming | API remove / reject | Configs and enums using Full/Delete aliases fail or type-error |
| Dry-run remove vocabulary | Rename | Code reading `deletedPaths` / `action: 'delete'` must update |
| Constructor requires rules | Behavior | `new FieldRedactor()` / `new FieldRedactor({})` throws |
| `@internal` root exports | Export remove | Deep type imports from package root fail |

Redaction **semantics** for shallow/deep/opaque/remove, path rules, value patterns, and COW are unchanged when configs already use preferred names.

---

## 1. Naming: drop Full / Delete aliases

### Config fields

| 1.x (removed) | 2.0 |
| --- | --- |
| `fullSecretKeys` | `opaqueSecretKeys` |
| `deleteSecretKeys` | `removeSecretKeys` |

**Implementation notes:**

- Remove from `FieldRedactorConfig` / `SecretManagerConfig` in `src/types.ts`.
- Delete `SECRET_REGEX_ALIAS_FIELDS` and alias merge in `normalizeFieldRedactorConfig` (`src/config/redactionRules.ts`).
- Stop merging legacy lists in `SecretManager` (`src/rules/secretManager.ts`).
- Drop deprecation warnings in `validateFieldRedactorConfig` (`src/config/configValidator.ts`).
- Update `hasExplicitRedactionRules` / `RULE_LIST_FIELDS` so only canonical fields count (aliases gone).
- Reject unknown legacy keys? Prefer TypeScript omission + ignore-at-runtime (no silent merge). Optional: warn or throw if `fullSecretKeys` / `deleteSecretKeys` appear on a plain object — **prefer throw in `strict` / always throw in 2.0** for fail-fast upgrades. Decision for implementers: **reject at validate time** with a clear `FieldRedactorConfigurationError` if those keys are present (even empty arrays), so mis-migrated configs do not silently no-op.

### Enum members

| 1.x (removed) | 2.0 |
| --- | --- |
| `CustomObjectMatchType.Full` | `CustomObjectMatchType.Opaque` |
| `CustomObjectMatchType.Delete` | `CustomObjectMatchType.Remove` |

Numeric values of Opaque/Remove stay `1` / `0`. Remove the duplicate enum members from `src/types.ts`.

### Builder

| 1.x (removed) | 2.0 |
| --- | --- |
| `.delete(...patterns)` | `.remove(...patterns)` |

Remove `delete()` from `FieldRedactorConfigBuilder` (`src/api/fieldRedactorConfigBuilder.ts`).

### Docs / examples / tests

Update every guide, example, and test that still uses Full/Delete/`fullSecretKeys`/`deleteSecretKeys`/`.delete()`.

## 2. Dry-run: `delete` → `remove` vocabulary

| 1.x | 2.0 |
| --- | --- |
| `DryRunReport.deletedPaths` | `removedPaths` |
| `DryRunPathRule.action: 'delete'` | `'remove'` |
| Internal helpers named `attributeDeletePath`, etc. | Rename to remove vocabulary |

**Types** (`src/types.ts`):

```typescript
action: 'redact' | 'remove';
// ...
removedPaths: string[];
```

**Implementation touchpoints:**

- `src/dryrun/dryRun.ts` — report fields and path lists
- `src/rules/ruleResolver.ts` — attribution actions / helpers
- Unit tests: `dryRunAttribution`, `fieldRedactor.dryRun`, `ruleResolver*`, builder dry-run expectations
- Docs: README, config reference, anti-patterns, examples, older migration guides that cite `deletedPaths` (update in place where they describe current API; historical release notes can stay)

No compatibility aliases for the old dry-run field names in 2.0.

## 3. Constructor: require explicit rules (option A)

### 1.x behavior

- `new FieldRedactor()` / empty config → redact **all** values + warning.
- `FieldRedactor.createSafe(config)` → throws if no explicit rules.

### 2.0 behavior (done)

- `new FieldRedactor(config)` and `buildRedactor()` / `buildSafeRedactor()` require the same rule bar as `createSafe`:
  - at least one non-empty: `secretKeys`, `deepSecretKeys`, `opaqueSecretKeys`, `removeSecretKeys`, `customObjects`, `valuePatterns`, or `pathRules`
- Throw `FieldRedactorConfigurationError` with a message that no longer mentions the legacy all-redact default.
- `createSafe` is a thin alias of the constructor (same guard).
- Empty-config warning path (“All values will be redacted…”) is **removed**.

**Explicit non-breaks:**

- `secretKeys: []` combined with other rule lists still follows existing `resolveSecretKeys` semantics.
- `strict` / `onConfigWarning` remain for other validation warnings.

**Touchpoints:** `src/api/fieldRedactor.ts`, builder `buildRedactor()`, tests that construct with no rules, anti-patterns / README / config reference.

## 4. Remove `@internal` root exports (done)

Stopped re-exporting from `src/index.ts` (types remain in `src/types.ts` for internal imports):

| Removed from public export |
| --- |
| `JsonFunction` |
| `JsonLeafValue` |
| `RedactablePrimitive` |
| `RedactedPrimitive` |
| `SecretSpecifierValue` |
| `TraversableJson` |

**Keep exported** (supported public surface): e.g. `JsonPrimitive`, `JsonObject`, `JsonArray`, `JsonValue`, `RedactableInput`, `RedactorInput`, `Redactor`, `SyncRedactor`, config/dry-run types, errors, presets, builder, `FieldRedactor`, validators.

`JsonRecord` was already not in `index.ts` — left internal.

## 5. Out of this breaking surface

Unchanged by design:

- Path-rule modes and matching
- Value-pattern redaction
- Copy-on-write / `cloneInput`
- Sync vs async APIs
- Package `exports` (root-only, already 1.6)
- Dry-run single-pass attribution during traversal (still deferred)

Housekeeping that is **not** a public break (can ship in the same major):

- Rename `objectRedactor.*` test files / helpers
- Clarify historical `docs/release-notes/2.x.md` vs npm 2.0.0 in the index

2. Constructor / `createSafe` alignment (option A).
