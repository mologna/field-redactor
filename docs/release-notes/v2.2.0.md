# Release notes — v2.2.0

Field Redactor **2.2.0** lets one instance use a different transform per field. A secret can go through an async function you supply (for example Voltage FPE) while a card number keeps its last four digits. The library does not bundle Voltage. It only calls the function you pass.

**Upgrade from 2.1.0:** Install `2.2.0`. Existing regex configs keep working. Code that reads `secretKeys`, `deepSecretKeys`, or `opaqueSecretKeys` as `RegExp[]` must handle `RegExp | KeyRedactorRule`.

## Highlights

| Area                     | What changed                                                                  |
| ------------------------ | ----------------------------------------------------------------------------- |
| **Per-field transforms** | `{ keys, redactor?, syncRedactor? }` on shallow, deep, opaque, and path rules |
| **Partial masks**        | `maskKeepLast` and `maskKeepLastDigits`                                       |
| **Redactor context**     | Optional second argument `{ key, path }`                                      |
| **Sync failure**         | An in-place sync walk that throws undoes its writes on the same objects       |

## Per-field redactors

```typescript
import { FieldRedactorConfigBuilder, maskKeepLastDigits } from 'field-redactor';

const voltageFpe = async (value: unknown) => voltage.encrypt(String(value));

const redactor = FieldRedactorConfigBuilder.create()
  .shallow({ keys: [/ssn/i, /taxId/i], redactor: voltageFpe })
  .shallow({ keys: [/cardNumber/i, /pan/i], syncRedactor: maskKeepLastDigits(4) })
  .shallow(/email/i)
  .deep({ keys: [/account/i], redactor: voltageFpe })
  .pathRule({ path: 'billing.card.number', mode: 'shallow', syncRedactor: maskKeepLastDigits(4) })
  .buildSafeRedactor();
```

`redact()` uses a rule's `redactor` when it has one. `redactSync()` uses that rule's `syncRedactor`. A rule with `redactor` and no `syncRedactor` throws only when a matching value is reached. If that throw happens during an in-place sync walk, each write is undone on the object that changed, so a nested object a caller already holds keeps its identity. The walk does not clone the input first.

Opaque and deep transforms are inherited by descendants until a more specific rule sets its own. Shallow transforms are not inherited. `remove` stays regex-only.

`maskKeepLastDigits(4)` turns `4111-1111-1111-4242` into `****-****-****-4242`. A count of 0, or a value with `count` digits or fewer, masks every digit.

See [Secret key modes](../guides/secret-key-modes.md#per-field-redactors) and the [configuration reference](../reference/config.md).
