# Release notes — v2.1.0

Field Redactor **2.1.0** fixes numeric (and boolean) secret values being left unmasked when a custom `redactor` / `syncRedactor` only handled strings.

**Upgrade from 2.0.0:** Install `2.1.0`. No config changes required. If your custom redactor used `typeof val === 'string'` guards, numbers such as `{ "mdn": 1234567890 }` are now coerced to `"1234567890"` before your function runs.

## Highlights

| Area | What changed |
| --- | --- |
| **Custom redactors** | Non-string scalars coerced with `String(...)` before `redactor` / `syncRedactor` |
| **Nullish** | `null` / `undefined` still passed through unchanged when redacted |

## Bug fix

Secret key modes already selected numeric fields for redaction, but string-only custom redactors often returned the raw number unchanged:

```typescript
const syncRedactor = (val) => (typeof val === 'string' ? 'REDACTED' : val);

// Before 2.1.0 — number leaked
FieldRedactor.createSafe({ secretKeys: [/mdn/i], syncRedactor })
  .redactSync({ mdn: 1234567890 });
// → { mdn: 1234567890 }

// After — coerced to "1234567890", then redacted
// → { mdn: 'REDACTED' }
```

The default `"REDACTED"` redactor was unaffected. Value-pattern matching already used `String(value)` for numbers.

### What is coerced

| Value | Passed to custom redactor |
| --- | --- |
| `string` | unchanged |
| `number` (including `0`) | `String(number)` |
| `boolean` (when `ignoreBooleans` is `false`) | `String(boolean)` |
| `null` / `undefined` (when `ignoreNullOrUndefined` is `false`) | unchanged |
